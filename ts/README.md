# Terminal Poker (TypeScript)

A real, playable Texas Hold'em engine (blinds, betting rounds, side pots, hand evaluation) with several ways to play:

- **Local hot-seat** — pass the terminal (or a browser tab) around a table of 2-8 players.
- **Vs AI** — you against 1-7 computer opponents, offline, in the terminal or the browser.
- **Online, terminal client** — host a game server, others join from their own terminal over a WebSocket.
- **Online, web client (server)** — the same server also serves a browser UI, so players can join from a browser instead of a terminal.
- **Online, web client (P2P, no server)** — host a table, join by code, or quick-match into a random open table, entirely peer-to-peer over WebRTC (no backend to deploy at all), with built-in text and voice chat.

You can also export the current session (players, chips, blinds, hand number) to a hexadecimal `.txt` file and resume later — from either the CLI or the browser.

> A second, independent Python implementation of this same idea lives at [`../python`](../python) — see the
> top-level [README](../README.md) for how the two relate.

**Shared engine, three surfaces.** `src/game`, `src/ai`, and `src/utils/serializer.ts` have zero Node-specific
dependencies (no `fs`/`path`). The exact same source compiles to `dist/` for the CLI and WebSocket server
(`tsc`), and bundles into `public/engine.bundle.js` for the browser (`esbuild`) — one hand evaluator, one set of
betting rules, one hex codec, used everywhere.

## Installation
```
cd ts
npm install
```

## Tests
```
npm test
```
Covers hand evaluation (including edge cases like the ace-low wheel and kicker ordering), full betting-round
progression (blinds, raises reopening the action, side pots, showdown payouts, chip conservation), the hex
save/load round trip (including tamper detection), and the AI's decision logic (including the big-blind
"option" case where a bet already exists but there's nothing left to call — that has to be a *raise*, not a
*bet*).

## Playing locally (hot-seat / vs AI, terminal)
```
npm start
```
Choose how many seats and, per seat, whether it's a human or an AI opponent. Before each human's turn the game
asks you to pass the device to them and hides the hole cards until they press Enter; AI seats act automatically.
Type `save` at any action prompt, or between hands, to export the session.

Resume a saved local session:
```
npm run build
node dist/main.js local --load poker-save-hand12-....hex.txt
```

## Playing on the web — no server required for local/AI play

The web client at `public/index.html` is a **static page**: build the engine bundle once and open it directly,
no backend needed for Local Pass & Play or Vs AI.

```
npm run build:pages      # bundles src/ into public/engine.bundle.js and public/p2p.bundle.js via esbuild
open public/index.html   # or serve the public/ folder with any static file server
```

The landing screen offers:
- **Local Pass & Play** — hot-seat in the browser, with a "pass the device" reveal gate between turns, same as the terminal.
- **Play vs AI** — you against 1-7 bots, entirely client-side.
- **Online (Server)** — connects to a WebSocket server you specify (see below) — the one mode that needs a backend.
- **Online (P2P)** — host, join by code, or quick-match, with no backend at all — see below.
- **Load a hex save** — paste a hex block or pick a `.txt` file to resume any previous local/AI session, right from the landing screen.

## Online (P2P) — no server, with voice + text chat

This mode uses [Trystero](https://github.com/dmotz/trystero) for serverless WebRTC: peers find each other and
exchange connection info over the public Nostr relay network (no account, no server of ours), then talk
directly over WebRTC — game state, chat, and voice audio all peer-to-peer. Whoever creates the table runs the
actual `Game` and is authoritative; everyone else just renders whatever state they're sent and forwards their
intent back. `public/p2p.bundle.js` (built by `npm run build:p2p`) is a small bundle of `trystero` on top of
the same shared engine — no separate server process, so it works straight from the deployed GitHub Pages site.

Three ways to connect, all from the "Online (P2P)" join screen:
- **Host a new table** — generates a 6-character room code to share with friends (not discoverable by strangers).
- **Join by code** — enter a code someone gave you.
- **Quick match** — briefly checks a public lobby for an open table and joins one at random; if none are open,
  you become the host and get listed there for the next person who quick-matches.

Click **"🎤 Enable Voice Chat"** on the table screen to open your mic and start talking — it's full-mesh (every
peer connects directly to every other peer), which is fine for a table of up to 8 but not built for much larger
groups. Two things worth knowing: the host's tab has to stay open for the table to keep running (there's no
server to persist it), and very restrictive networks/firewalls can occasionally block a direct P2P connection
(there's no paid relay-of-last-resort, i.e. no TURN server, just STUN).

## Deploying the web client to GitHub Pages

`.github/workflows/deploy.yml` (at the repo root) builds and deploys `ts/public` automatically on every push to
`main`: it runs `npm ci`, `npm test`, `npm run build:pages` (both bundles), then publishes `ts/public` via
`actions/upload-pages-artifact` + `actions/deploy-pages`. To turn it on for your fork:

1. Push this repo to GitHub.
2. In the repo's Settings → Pages, set **Source** to "GitHub Actions".
3. Push to `main` (or run the workflow manually from the Actions tab) — the page appears at
   `https://<you>.github.io/<repo>/`.

Because `index.html` references its scripts/styles with relative (not root-absolute) paths, it works correctly
whether it's served from a domain root or a project subpath like `/poker-game/`.

Online (P2P) needs nothing further — it works straight from that deployed static page. Online (Server) still
needs somewhere to run `npm run start:server` (Pages can't host it — it's static-only): deploy it anywhere that
runs Node (a small VM, Render, Fly.io, etc.) and enter its `wss://host/ws` URL in that mode's join screen.

## Playing online (self-hosted server)

Start a server (also serves the web client):
```
npm run start:server 3000
```
This prints:
- a web client URL — open `http://localhost:3000` in a browser to join and play
- a WebSocket URL for terminal clients — `ws://localhost:3000/ws`

The server terminal itself is an admin console: type `start` to deal the next hand once at least two players have
joined, `save` to export the session to a hex file, or `quit` to stop the server.

Join from another terminal:
```
npm run start:client ws://localhost:3000/ws Alice
```
Or open the printed URL in a browser for the web client. To play over the internet (not just your local network),
port-forward or tunnel the server's port to the host machine.

## The hex save system

`src/utils/serializer.ts` exports the codec directly:

```ts
exportSaveToHex(payload: unknown): string       // JSON -> UTF-8 bytes -> hex, with a comment header
importSaveFromHex<T>(hexString: string): T      // reciprocal: strips comments/whitespace, decodes, JSON.parse
```

`src/utils/export.ts` (Node) and `src/web/browserEntry.ts` (browser) layer `exportGameToHex(game)` /
`importGameFromHex(hex)` on top, which additionally know how to turn a `Game` into/from that payload
(`Game#exportSave()` / `Game.fromSave()`), including AI seats. A save file looks like:
```
# POKER-SAVE-V1 (hex-encoded JSON — do not edit by hand)
7b2276657273696f6e223a312c...
```
- **Local/AI (terminal)**: type `save` at an action prompt, or at the between-hands menu.
- **Local/AI (web)**: click "Export Save (hex)" — downloads a `.hex.txt` file.
- **Terminal client / server admin console**: type `save` at the idle or action prompt.
- **Loading it back**: `node dist/main.js local --load <file>` in the terminal, or paste the hex / pick the
  file in the web client's "Load a hex save" panel — both reconstruct chips, blinds, hand number, and which
  seats were AI.
